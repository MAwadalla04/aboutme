# Portfolio design critique

## Method

Applied Anthropic `frontend-design`, `impeccable`, and `ui-ux-pro-max`. This is a source-and-detector review; live browser inspection was unavailable because no browser session was exposed.

## Assessment A — design director

### Design-specificity verdict

Specific content, generic composition. EB Garamond, Inter, the autograd graph, and the project claims give the portfolio an authored point of view. But the glass pills, gradient grid, ambient blobs, floating social dock, auto-carousel, modal cards, and `/useless` link are interchangeable portfolio tropes that compete with the person and the work.

### Cognitive load and emotional journey

The first viewport is calm and technically interesting, but it does not yet answer “why should I hire this person?” The graph competes with the headline, while “Software Engineer” is too broad to carry the thesis. About and Experience build credibility. Projects should be the peak, but the moving horizontal shelf and hidden modal details create friction exactly where evidence should be easiest to scan. Contact is clean but could close with a stronger, more direct invitation.

### Strengths

- The serif/sans/mono type system creates a credible editorial-engineering voice.
- The content has real proof: precision, deployment, open-source status, scale, and concrete technologies.
- The resume CTA is visually legible and the interaction language is generally restrained.

### Priority issues

1. **P1 — Projects are hidden behind interaction.** `Projects.js:69-79` renders a step carousel; `AppleCardsCarousel.js:173-195` auto-advances every 4 seconds. Users cannot compare all four projects at a glance, and “Open details” forces a modal before reaching links or proof. Make LegalDocuMan a featured case study and use a stable grid/stack for the remaining work. Suggested command: `$impeccable layout`.
2. **P1 — Mobile navigation disappears without a replacement.** At `index.css:1145-1147`, `.nav-links` is `display: none` at the mobile breakpoint. There is no menu, skip link, or alternative section navigation. Suggested command: `$impeccable adapt`.
3. **P1 — Project modal is not fully accessible.** `AppleCardsCarousel.js:297-340` has no `role="dialog"`, `aria-modal`, labelled relationship, focus trap, or focus return. Escape and outside click exist, but keyboard users can still lose context. Suggested command: `$impeccable harden`.
4. **P2 — The visual language is over-specified.** The grid, three floating hero shapes, autograd animation, glass metadata pills, rounded dark cards, floating dock, and animated underlines all ask for attention. Keep one signature device—probably the autograd graph—and make the rest quieter. Suggested command: `$impeccable quieter`.
5. **P2 — Accent tokens no longer communicate accents.** `index.css:17-18` maps “blue” to gray and “orange” to white, so project accent names do not produce meaningful differentiation. Either define a deliberately monochrome system or use two intentional project colors consistently. Suggested command: `$impeccable colorize`.

### Persona red flags

- **Recruiter:** lands on a generic “Software Engineer” statement and must operate a carousel/modal to find evidence.
- **Keyboard or screen-reader visitor:** mobile navigation is unavailable, the modal lacks dialog semantics, and the graph is marked `aria-hidden="true"` while its nested SVG declares an accessible name (`Hero.js:87-88`).
- **Mobile visitor:** horizontal project movement, fixed dock, and dense cards increase navigation and scanning cost.
- **Hiring engineer:** technical claims are strong, but the card surface gives little immediate sense of architecture, screenshots, demos, or the decision-making behind each project.

### Minor notes

- `getCardStep()` uses 224/384px (`AppleCardsCarousel.js:17-20`) while cards render at up to 21rem (`index.css:1612-1637`), so arrow/autoplay movement is not aligned to the actual card width.
- `h2::after` animates width on section hover (`index.css:120-134`); this is a low-value desktop-only interaction.
- The detector flags the two-axis hero grid (`index.css:287-297`), spring/bounce easing (`index.css:1272-1277`), and a thick accent border on a rounded card (`index.css:1600-1611`).

### Provocative questions

- Is the portfolio trying to feel like an editorial profile, an AI systems notebook, or a product engineer’s case-study site? The current mix says all three.
- Should a visitor understand the value proposition before seeing the autograd graph?
- Would the work feel more impressive if every project were visible, with motion reserved for the evidence itself?

## Assessment B — evidence and UX review

### Findings

- **Responsive:** mobile nav is removed at the 768px breakpoint with no replacement.
- **Interaction:** autoplay, hidden horizontal scrollbars, and modal-only details make project discovery less predictable.
- **Accessibility:** modal semantics/focus management are incomplete; hero graph semantics conflict with its parent `aria-hidden`.
- **Consistency:** project color variables are semantically named but visually monochrome; card width and carousel step disagree.
- **Motion:** reduced-motion handling covers some CSS animations, but the React section reveal and carousel interval are not preference-aware.
- **Performance/clarity:** the page layers several decorative effects before it has established a strong personal thesis.

### Detector findings

The required detector found four warnings/advisories: rounded card plus thick accent border, spring bounce easing, animated underline width, and a two-axis grid background. These are not catastrophic defects, but they reinforce the broader craft diagnosis: too many ornamental behaviors for a page whose strongest asset is its content.

### Browser status

Browser verification was attempted, but no browser was available in the session (`agent.browsers.list()` returned an empty list). No screenshot or live overlay claims are made.

## Recommended order

1. Rewrite the hero around a specific engineering thesis and one proof-oriented CTA.
2. Replace the project step carousel with a scannable featured-plus-grid layout; remove autoplay.
3. Restore usable mobile navigation and add a skip link/focus-visible treatment.
4. Harden the project dialog or remove the dialog in favor of inline expansion.
5. Remove two or three decorative systems and let the typography, evidence, and one signature graphic carry the identity.
